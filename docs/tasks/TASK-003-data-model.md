# TASK-003 — Data model, migrations, DB health, do-not-contact

## Goal
The core tables in Postgres with Drizzle migrations applied at container start, `/api/health` checking the DB, and
the do-not-contact check that every future outbound path must use.

## Scope
1. Schema (`src/server/db/schema.ts`): companies, contacts, competitor_links, audits, deals, activities, drafts,
   do_not_contact; enums for stage, source, group, activity type, draft status, DNC kind.
2. Database-enforced rules: one deal per company; a draft can be `sent` only with `approved_at` (ADR-004);
   an e-mail contact needs `email_source` (ADR-007); lower-case e-mails/DNC values; score 0–100; rating 0–50.
3. Migrations: `drizzle/` generated by drizzle-kit, applied at start when `RUN_MIGRATIONS=1` (instrumentation).
4. Health: `{status, sha, db}`, 503 on DB failure/timeout, no error details.
5. `isBlocked()` / `addToDnc()` (no remove — opt-outs are permanent), `normalizeEmail()`, `domainOf()`.
6. CI: Postgres service, integration tests, Docker run with migrations; deploy smoke requires `"db":"ok"`.

Out of scope: proposals, payments, projects (TASK-013/014), auth (separate task).

## Acceptance criteria
Unit + integration tests green locally and in CI; container applies migrations and reports `"db":"ok"`.
